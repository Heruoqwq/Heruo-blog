# Heruo OJ

公开文章、账号注册、个人写作和私密待办。

## 使用

- 博客： https://heruoqwq.github.io/Heruo-blog/
- 注册：点击「注册」，填写用户名、密码和确认密码。用户名以字母开头，包含 3–24 位字母、数字或下划线；密码 8–200 位。
- 登录：使用用户名或账号 ID。注册后自动登录。
- Heruo：ID 为 **1**，用户名 **heruo**，身份为超级管理员，密码沿用原有管理密码。
- 文章：每人可新建、编辑、发布、保存草稿和导出自己的 Markdown 文章。首页分「主站推荐」「个人文章」；只有超级管理员可推荐或取消推荐已发布文章。草稿不进入推荐。
- 个人主页：点击作者名或「我的 → 个人主页」，查看该用户的全部公开文章，以及去重后的已通过公开题目。草稿、私密待办、隐藏题目和账号凭据不会出现在个人主页。
- 待办：每个账号独立保存，可添加、完成、撤销完成、删除。
- 超级管理员：可管理所有文章，查看账号列表并停用或启用普通账号；不能停用 ID 1。
- 个人待办仅账号本人可访问；超级管理员也不能读取他人的待办。
- 原有文章、待办和有效会话继续归 ID 1 所有，无需重新导入。

## GitHub Pages 设置

在仓库 **Settings → Pages** 中选择：

1. Source：**Deploy from a branch**。
2. Branch：**main**。
3. Folder：**/docs**。
4. 点击 **Save**，等待 GitHub Pages 构建完成。

`docs/` 包含构建好的网页。GitHub Pages 托管前端；密码验证、文章和私密待办由配套的 Cloudflare Workers / D1 服务处理。文章发布和待办操作不需要 GitHub Token。

## 账号与数据

- 密码使用独立随机盐和 PBKDF2 摘要保存，明文密码不会进入源码或客户端构建。
- ID 1 在接受注册前由服务端保留为 Heruo。初始密码摘要使用已有运行时 secret，普通注册不能指定 ID 或权限。
- 会话有效期为 24 小时，数据库仅保存会话令牌的摘要；退出或停用账号会使相应会话失效。
- 文章修改、草稿读取、用户管理和待办操作均由服务端检查权限。
- 新增的归属字段允许为空；旧数据按 ID 1 处理，迁移保留原有数据。
- 账号、文章和任务存储在后端数据库，GitHub 源码不包含这些数据。

## 开发

Node.js >=22.13.0，pnpm 11.25.0。

```bash
pnpm install --frozen-lockfile
pnpm run typecheck
pnpm test
pnpm run build:github
pnpm run build
```

修改前端后运行 `pnpm run build:github`，提交更新后的 `docs/`。文件存储绑定为 `BUCKET`（R2），结构化数据绑定为 `DB`（D1）。后台源代码位于 `app/server/api.ts`，数据库 schema 位于 `db/schema.ts`，迁移位于 `drizzle/`。配套服务使用 Sites 的发布流程部署，GitHub Pages 本身不运行服务端代码。

运行时配置键：`ADMIN_PASSWORD_HASH`（secret）、`BLOG_ALLOWED_ORIGIN`。如果更换域名，须同步后端来源配置及 `github/main.tsx` 的 API 地址。后端项目身份配置位于 `.openai/hosting.json`。

## 可折叠提示块

在文章正文或编辑器中使用：

````markdown
:::info[code]
这里可以写 Markdown、$LaTeX$ 公式以及代码：

```cpp
cout<<1;
```
:::
````

`code` 是可修改的标题。默认收起，点击整行标题可以展开，再次点击收起。未填写标题时显示「提示」。需要默认展开时写 `:::info[标题]{open}`。

也支持 `note`、`tip`、`warning`、`danger` 和 `details`。嵌套提示块时，外层使用四个冒号 `::::`，内层使用三个冒号 `:::`。代码块里的 `:::` 保持原样显示。

## 在线 OJ

- 题库入口： https://heruoqwq.github.io/Heruo-blog/#/oj
- 注册用户登录后可提交 C++17 程序。代码使用 GCC 14.1.0、C++17、O2，通过 Judge0 独立沙箱执行；程序不能联网。
- 超级管理员可新建和编辑题目、发布或隐藏题目、填写 Markdown 题面和公开样例、导入或编辑隐藏测试点。
- 默认包含 A1000「A+B」示例题。时间限制 100～5000 ms，内存限制 16～512 MB；每题 1～50 个测试点，每点输入与输出合计不超过 16 MiB，每题合计不超过 256 MiB。
- 测试数据：题目管理支持多选同名 `.in/.out` 文件（如 `test1.in/test1.out`），按文件名自然排序配对，批量导入替换当前数据；也可逐点上传、预览、下载或移除文件。导入后点击「保存」生效。空输出文件有效；文件须为 UTF-8 文本。JSON 导入上限 64 MiB，大文本会自动转成文件上传。
- 文件保存在私有 R2 存储中，数据库只记录文件编号；读取、预览和下载均需超级管理员权限。单个大文件不会放进题目元数据请求，评测请求按数据量和最多 20 点分批发送。
- 测试点可设 1～100 的权重。分数为通过权重占总权重的百分比向下取整；全部通过显示 AC。支持 WA、TLE、MLE、RE、CE，评测服务异常显示 JE。
- 普通访客可看公开题目的提交状态；只有提交者本人和超级管理员可查看源代码、编译信息和逐点结果。逐点结果支持展开查看判定、时间、内存、权重、限制及退出信息；超级管理员还可查看截断的运行输出和错误日志。隐藏测试输入、预期输出、上游查询令牌不会返回访客。
- 提交时记录题目版本、时限、内存限制和测试点权重。修改题目只影响后续提交，不覆盖已有记录。
- 提交后程序在独立服务执行；结果页自动更新，记录页查询也会同步最近待完成的结果。服务超时或故障不会判为 AC。
- 默认评测地址为 https://ce.judge0.com ，代码与测试数据会发送到该服务；共享服务的可用性和容量由服务方决定。可配置自建或专用 Judge0，密钥仅保存在后端。
- 为限制共享服务消耗，同账号同 IP 每 15 分钟最多提交 5 次，全站每 15 分钟最多 30 次。
- 首版为传统题评测，暂不包含交互题、自定义 checker 和捆绑子任务。

测试数据 JSON 格式如下，也可以直接导入由该数组构成的 JSON 文件：

```json
{
  "cases": [
    {"input": "1 2\n", "output": "3\n", "weight": 1},
    {"input": "-5 8\n", "output": "3\n", "weight": 1}
  ]
}
```

可选运行时配置：JUDGE0_URL（HTTPS 地址）、JUDGE0_TOKEN（secret，作为 X-Auth-Token 发送）、JUDGE0_LANGUAGE_ID（默认 105，需匹配对应实例的 C++ 编译器）。切换服务后请重新提交尚未完成的程序。配置项通过 Sites 环境设置保存，随后重新部署生效。

评测异常时显示具体服务错误，提交者与超级管理员可在结果页点击「重新评测」；只有 JE 允许重评，题目版本变化时要求新提交。旧版尚未发送成功的 JE 记录会自动补发一次，不会无限重试。回归测试包含真实 Workers 运行时，评测请求使用 manual 重定向模式，拒绝重定向响应。
